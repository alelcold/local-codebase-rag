#### Problem 2: a Simplified refusal scored "not refused", and invented code could pass as a refusal

- **Problem**: group D, out-of-scope Q22 is a refusal, but the report said "not refused". Separately, a trick-question answer was counted as refused whenever it contained a refusal phrase and none of a few forbidden words, even if it went on to describe files or functions the project does not have.


  for the answer 「我无法提供关于付款流程的详细信息…」.
- **Cause**: refusal keywords were plain substrings of the Traditional forms (無法, 沒有找到); 无法 is a different code point. Five copies of the list (four question lists and `REFUSAL_PHRASES`) had to be kept in sync by hand. The only fabrication signal was the per-question forbidden list.

Answers are checked for file names and code-shaped symbols that exist nowhere in the project; a trick question with a refusal phrase and a forbidden word or unknown name is "not refused: refusal phrase, but suspected fabrication", for a person to check (ADR 0019).

### 遇到的問題

#### 問題 2：簡體拒答被算成「未拒答」，編造的程式碼也能被算成拒答

- **問題**：D 組範圍外第 22 題是拒答，報告卻寫「not refused」。另外，陷阱題的回答只要有拒答字句、沒有那幾個禁用字，就算拒答，即使後面描述了專案中沒有的檔案或函式。
- **錯誤訊息**：沒有錯誤；報告中的那一行是

  ```text
  | 22 | 陷阱題 | 10.0 s | 15.9 s | 57 | — | — | — | — | 0/1 (**not refused**) | 无关于内细为这处务码阅统档开发队联获 | 1 | …
  ```

  回答是「我无法提供关于付款流程的详细信息…」。
- **原因**：拒答關鍵字只是繁體寫法的子字串比對（無法、沒有找到），「无法」是不同的字碼。清單有五份（四題陷阱題清單與 `REFUSAL_PHRASES`），要手動同步。唯一的編造訊號是每題的禁用字清單。
- **解法**：`REFUSAL_TRAD_SIMP` 列出每個中文拒答字句與它的簡體寫法，比對時兩者都試；拒答關鍵字不在清單裡時，單元測試會失敗。回答中提到專案裡完全不存在的檔名與程式碼形式的符號會被找出；陷阱題有拒答字句但有禁用字或不存在的名稱時，標示為「not refused: refusal phrase, but suspected fabrication」，由人確認（ADR 0019）。
