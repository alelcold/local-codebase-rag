## Problems

### Problem 1: Two ADRs numbered 0016

- **Problem**: `docs/decisions/` had two files with the same number, so "ADR 0016" meant two different things in links and comments.
- **Error message**: none; `ls docs/decisions` showed

  ```text

  0016-refuse-out-of-scope-questions-in-the-prompt.md
  ```

- **Cause**: Both ADRs were written on 2026-11-03 in different pieces of work, each taking "the next free number" from the list as it was then. Nothing checks that numbers are unique. The README ADR index listed only the Mac benchmark one, so the prompt v3 ADR was also missing there.
- **Fix**: The Mac benchmark ADR became 0017 (file renamed, title and every link and "(ADR 0016)" that meant the benchmark updated in `README.md`, `CLAUDE.md`, `docs/metrics.md`, the experiment plan, the 2026-11-03 devlog and the resume); prompt v3 keeps 0016. The Codespaces defaults ADR is 0018. The README index now lists 0016, 0017 and 0018.
- **Not fixed (code was out of scope)**: `scripts/benchmark-mac.sh` (comment, line 11) and `scripts/benchmark_summary.py` (the header it writes into the generated summary, lines 168 and 171) still say "ADR 0016" for the benchmark. Change them to 0017 in a code PR. A cheap guard would be a unit test that fails when two files in `docs/decisions/` share a number.

## 遇到的問題

### 問題 1：有兩份編號 0016 的 ADR

- **問題**：`docs/decisions/` 有兩個同編號的檔案，所以連結與註解裡的「ADR 0016」指的是兩個不同的東西。
- **錯誤訊息**：沒有；`ls docs/decisions` 顯示

  ```text
  0016-one-command-mac-benchmark.md
  0016-refuse-out-of-scope-questions-in-the-prompt.md
  ```

- **原因**：兩份 ADR 都是 2026-11-03 在不同的工作中寫的，各自從當時的清單取「下一個可用編號」。沒有任何檢查確保編號唯一。README 的 ADR 索引只列了 Mac 實測那份，所以提示 v3 的 ADR 在索引裡也漏掉了。
- **解法**：Mac 實測的 ADR 改為 0017（檔案改名，標題與所有指向它的連結與「(ADR 0016)」都更新，涵蓋 `README.md`、`CLAUDE.md`、`docs/metrics.md`、實驗計畫、2026-11-03 的 devlog 與履歷）；提示 v3 維持 0016。Codespaces 預設值的 ADR 是 0018。README 索引現在列出 0016、0017、0018。
- **沒有處理（程式碼不在範圍內）**：`scripts/benchmark-mac.sh`（第 11 行的註解）與 `scripts/benchmark_summary.py`（寫進產生摘要的標頭，第 168、171 行）仍把 Mac 實測寫成「ADR 0016」，請在程式碼的 PR 改成 0017。一個便宜的防護是加單元測試：`docs/decisions/` 有兩個檔案同編號就失敗。
