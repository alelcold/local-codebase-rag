# Devlog 2026-10-30 — Architecture design and cloud build

> English first; 繁體中文版本在下方.

## What I did

- Designed the architecture: Ollama natively on the Mac host (LLM + embeddings), with Qdrant, a FastAPI + LlamaIndex backend and a React frontend in Docker Compose. See ADR 0001–0004.
- Had a Claude Code cloud session build the whole system in one go (total cost about **USD 7**), including:
  - tree-sitter chunking for `.ts/.tsx/.js` by function or class, and Markdown chunking by heading;
  - incremental indexing based on per-file content hashes stored in Qdrant;
  - `/health`, `/index`, `/index/status` and `/query`, with answers that cite `file:start-end`;
  - `scripts/setup.sh`, `.env.example`, and a Traditional Chinese README;
  - a sample game project (`examples/sample-game-frontend/`, 20 files);
  - backend unit tests where Ollama is faked and Qdrant runs in in-memory mode.
- Verified the stack end to end in the cloud sandbox: real Qdrant v1.20, backend and nginx containers, plus a **fake Ollama HTTP server**, because the sandbox has no GPU and no real model.
- Opened PR #1.

## Problems

### Problem 1: Query fails after indexing from the CLI

- **Problem**: The API had started before any index existed. After `./scripts/index.sh` created the collection, every `/query` returned 502.
- **Error message**:

  ```text
  UnexpectedResponse: Unexpected Response: 400 (Bad Request)
  Raw response content:
  b'{"status":{"error":"Wrong input: Not existing vector name error: text-dense"},"time":0.000366461}'
  ```

- **Cause**: LlamaIndex's `QdrantVectorStore` checks the collection's vector layout (named `text-dense` vs. unnamed) **only in its constructor**. The API process created its store while the collection did not exist yet. The CLI indexer, a separate process, then created the collection with an unnamed vector, so the API kept querying a vector name that did not exist. The unit tests missed this because each test used a single store instance.
- **Fix**: `CodeVectorStore._store()` in `backend/app/store.py` rebuilds the wrapper whenever the collection's existence differs from when the wrapper was built. A regression test simulates the two-process case: `test_store_created_before_collection_sees_collection_made_elsewhere`. Lesson: in-memory fakes miss cross-process state bugs, so run an end-to-end test as well.

### Problem 2: Empty env vars from Compose silently disabled the nomic prefixes

- **Problem**: `nomic-embed-text` needs `search_query: ` and `search_document: ` prefixes. Compose passes an unset `${EMBED_QUERY_PREFIX-}` as an empty string `""`, which pydantic treated as "explicitly no prefix".
- **Error message**: none. This kind of bug fails silently and only lowers retrieval quality.
- **Cause**: Compose does not distinguish "unset" from "empty" when it passes variables through.
- **Fix**: A field validator in `config.py` treats `""` as "auto", plus the test `test_empty_prefix_env_means_auto`.

### Problem 3: Docker Hub rate limit in the sandbox

- **Error message**:

  ```text
  unexpected status from HEAD request to https://registry-1.docker.io/v2/library/node/manifests/22-alpine: 429 Too Many Requests
  ```

- **Cause**: The cloud sandbox shares egress IPs, so it hits Docker Hub's anonymous pull limit.
- **Fix**: Retried pulls in the background with a one-minute backoff. This is environment-specific; nothing in the repo changed.

### Problem 4: pip/npm TLS errors inside `docker build` (sandbox only)

- **Error message**:

  ```text
  SSLError(SSLCertVerificationError(1, '[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: self-signed certificate in certificate chain (_ssl.c:1011)'))
  ```

- **Cause**: The sandbox routes HTTPS through a proxy that re-terminates TLS. Containers do not trust the proxy CA.
- **Fix**: For verification only, built scratch copies of the Dockerfiles with the CA added. The committed Dockerfiles stay clean.

### Smaller fixes found while reviewing chunk output

- Class fields that hold arrow functions (`private frame = () => {}`) were not split out like methods. They are now treated as methods.
- A Markdown heading followed directly by a sub-heading produced a one-line chunk. It is now merged into the next section.
- Ollama's default `num_ctx` is small and would silently truncate the retrieved code in the prompt. The backend now sends `num_ctx` explicitly (default 16384, configurable via `LLM_NUM_CTX`).

## Concepts learned

- **Docker on macOS cannot use the Metal GPU.** Containers run in a Linux VM, so Ollama must run natively. See ADR 0002.
- **`host.docker.internal`**: Docker Desktop provides it automatically. On Linux it needs `host-gateway`. See ADR 0006.
- **Embedding task prefixes**: some embedding models, such as nomic, expect different prefixes for queries and for documents.
- **The vector store is the source of truth for incremental indexing.** Storing a `file_hash` payload per chunk means wiping the volume simply triggers a full re-index, with no separate manifest that could drift.
- **Fakes vs. end-to-end tests**: fast unit tests with fakes plus one real-service smoke test caught a class of bug that neither caught alone.

- 設計架構：Ollama 直接裝在 Mac 主機上（LLM + embedding），Qdrant、FastAPI + LlamaIndex 後端、React 前端以 Docker Compose 執行。詳見 ADR 0001–0004。

  - `/health`、`/index`、`/index/status`、`/query`，回答會附上 `檔案:起始行-結束行` 引用；
  - `scripts/setup.sh`、`.env.example` 與繁體中文 README；
  - 範例遊戲專案（`examples/sample-game-frontend/`，20 個檔案）；
  - 後端單元測試：Ollama 以假物件取代，Qdrant 使用記憶體模式。
- 在雲端 sandbox 做端到端驗證：真實的 Qdrant v1.20、後端與 nginx 容器，再加上一個**假的 Ollama HTTP server**，因為 sandbox 沒有 GPU，也沒有真實模型。
- 開出 PR #1。

## 遇到的問題

### 問題 1：用 CLI 建立索引後，查詢失敗

- **問題**：API 在還沒有索引時就已啟動。執行 `./scripts/index.sh` 建立 collection 之後，每次 `/query` 都回傳 502。
- **錯誤訊息**：

  ```text
  UnexpectedResponse: Unexpected Response: 400 (Bad Request)
  Raw response content:
  b'{"status":{"error":"Wrong input: Not existing vector name error: text-dense"},"time":0.000366461}'
  ```

- **原因**：LlamaIndex 的 `QdrantVectorStore` **只在建構時**檢查 collection 的向量格式（具名的 `text-dense` 或未命名）。API 行程建立 store 時 collection 還不存在；之後 CLI 索引器（另一個行程）以未命名向量建立了 collection，API 卻持續用一個不存在的向量名稱查詢。單元測試沒抓到，因為每個測試只用一個 store 實例。
- **解法**：`backend/app/store.py` 的 `CodeVectorStore._store()` 在 collection 的存在狀態和建立 wrapper 時不同時，就重建 wrapper。另外新增回歸測試 `test_store_created_before_collection_sees_collection_made_elsewhere`，模擬兩個行程的情境。教訓：記憶體版的假物件抓不到跨行程的狀態問題，還是要跑一次端到端測試。

### 問題 2：Compose 傳入的空字串讓 nomic 前綴失效

- **問題**：`nomic-embed-text` 需要 `search_query: ` 和 `search_document: ` 前綴。Compose 會把未設定的 `${EMBED_QUERY_PREFIX-}` 傳成空字串 `""`，pydantic 把它當成「明確不要前綴」。
- **錯誤訊息**：沒有。這類問題不會報錯，只會讓檢索品質變差。
- **原因**：Compose 傳遞變數時不區分「未設定」和「空字串」。
- **解法**：在 `config.py` 加上 validator，把 `""` 視為「自動」，並新增測試 `test_empty_prefix_env_means_auto`。

### 問題 3：sandbox 遇到 Docker Hub 流量限制

- **錯誤訊息**：

  ```text
  unexpected status from HEAD request to https://registry-1.docker.io/v2/library/node/manifests/22-alpine: 429 Too Many Requests
  ```

- **原因**：雲端 sandbox 共用對外 IP，會撞到 Docker Hub 匿名拉取的上限。
- **解法**：在背景每分鐘重試一次。這是環境問題，repo 沒有任何修改。

### 問題 4：`docker build` 時 pip/npm 出現 TLS 錯誤（只發生在 sandbox）

- **錯誤訊息**：

  ```text
  SSLError(SSLCertVerificationError(1, '[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: self-signed certificate in certificate chain (_ssl.c:1011)'))
  ```

- **原因**：sandbox 的 HTTPS 流量會經過一個重新簽發 TLS 的代理，容器不信任代理的 CA。
- **解法**：只為了驗證，另外複製一份加入 CA 的 Dockerfile 來 build；repo 裡的 Dockerfile 保持乾淨。

### 檢查切塊結果時順手修正的小問題

- 存放箭頭函式的 class 欄位（`private frame = () => {}`）沒有像 method 一樣被切開；現在會視為 method。
- Markdown 標題下方直接接子標題時，會產生只有一行的片段；現在會併入下一個章節。
- Ollama 預設的 `num_ctx` 很小，會默默截斷提示詞裡引用的程式碼；後端現在會明確傳入 `num_ctx`（預設 16384，可用 `LLM_NUM_CTX` 設定）。

## 學到的概念

- **macOS 上的 Docker 用不到 Metal GPU**：容器跑在 Linux VM 裡，所以 Ollama 必須在主機上原生執行。見 ADR 0002。
- **`host.docker.internal`**：Docker Desktop 會自動提供；Linux 上需要 `host-gateway`。見 ADR 0006。
- **Embedding 任務前綴**：有些 embedding 模型（例如 nomic）的查詢和文件需要加不同的前綴。
- **向量資料庫就是增量索引的唯一依據**：每個片段都存一份 `file_hash`，清掉 volume 就等於下次完整重建，不需要另外維護可能不同步的 manifest。
- **假物件 vs 端到端測試**：快速的單元測試搭配一次真實服務的 smoke test，抓到了單靠任何一種都抓不到的問題。
