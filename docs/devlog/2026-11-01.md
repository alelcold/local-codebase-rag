## What I did

- Ran the whole flow in **GitHub Codespaces** (Linux, no GPU) before deploying to the Mac M2: setup → index the sample project → query from the UI.
- Used the small model `qwen2.5-coder:3b` because CPU-only inference with 14B is too slow for a quick check. `nomic-embed-text` stayed the embedding model.

  ```dotenv
  LLM_MODEL=qwen2.5-coder:3b
  ```

- Ran Ollama natively inside the codespace, not in Compose, to keep the same topology as the Mac.
- Compared GPU test environments for the larger models: AWS EC2 `g5.xlarge`, RunPod and Lambda. See ADR 0006.

## Problems

### Problem 1: Containers cannot reach Ollama on Linux

- **Problem**: `/health` reported Ollama as unreachable, even though `curl http://localhost:11434/api/version` worked inside the codespace.
- **Error message**:

  ```text
  {待補：貼上 /health 回傳的 ollama.error 或 docker compose logs backend 的錯誤}
  ```

- **Cause**: There are two Linux differences from Docker Desktop on the Mac:
  1. `host.docker.internal` is not defined automatically on Linux. It needs `extra_hosts: ["host.docker.internal:host-gateway"]`, which maps the name to the Docker bridge gateway IP. The compose file already includes this line.
  2. Ollama listens on `127.0.0.1` by default. A request from a container arrives at the bridge gateway IP, not loopback, so the connection is refused. Docker Desktop on macOS forwards to the host's loopback, which is why the Mac does not need this.
- **Fix**: Start Ollama listening on all interfaces:

  ```bash
  OLLAMA_HOST=0.0.0.0 ollama serve
  ```

  Security note: this exposes port 11434 on every interface. In Codespaces, keep port 11434 **private** in the Ports panel, and never make it public.

## Concepts learned

- **`host-gateway`** is a special value for `extra_hosts` that resolves to the host's IP on the default bridge network. It works on Docker Engine on Linux.
- **Listen address matters.** A service bound to `127.0.0.1` is reachable only from the same network namespace, and a container is a different namespace.
- **Small models for pipeline checks.** A 3B model is enough to prove that indexing, retrieval, citations and the UI work end to end. Answer quality must be judged with the target model (14B) on the target hardware.

## 遇到的問題

### 問題 1：Linux 上的容器連不到 Ollama

- **問題**：`/health` 回報無法連線 Ollama，但在 codespace 裡執行 `curl http://localhost:11434/api/version` 是正常的。
- **錯誤訊息**：

  ```text
  {待補：貼上 /health 回傳的 ollama.error 或 docker compose logs backend 的錯誤}
  ```

- **原因**：Linux 和 Mac 上的 Docker Desktop 有兩點不同：
  1. Linux 不會自動定義 `host.docker.internal`。需要 `extra_hosts: ["host.docker.internal:host-gateway"]`，把這個名稱對應到 Docker bridge 的 gateway IP。compose 檔裡已經有這一行。
  2. Ollama 預設只監聽 `127.0.0.1`。從容器來的連線會打到 bridge gateway IP，不是 loopback，所以連線會被拒絕。Mac 的 Docker Desktop 會把連線轉到主機的 loopback，所以在 Mac 上不需要這個設定。
- **解法**：讓 Ollama 監聽所有網卡：

  ```bash
  OLLAMA_HOST=0.0.0.0 ollama serve
  ```

  安全提醒：這樣 11434 埠會在所有網卡上開放。在 Codespaces 裡，請在 Ports 面板把 11434 維持在 **private**，不要設為 public。

## 學到的概念

- **`host-gateway`** 是 `extra_hosts` 的特殊值，會解析成主機在預設 bridge 網路上的 IP，適用於 Linux 上的 Docker Engine。
- **監聽位址很重要**：綁在 `127.0.0.1` 的服務只能從同一個網路命名空間連線，而容器屬於另一個命名空間。
- **用小模型驗證流程**：3B 模型就足以確認索引、檢索、引用與介面整條流程正常；回答品質則要用目標模型（14B）在目標硬體上評估。
