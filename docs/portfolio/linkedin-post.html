我用 US$100 的 AI 雲端額度，一週做出一套地端程式碼問答系統。
最意外的收穫是：試了 6 種常見的 RAG 技巧，最後只留下 1 個。

起點很簡單：想用中文問「無敵時間在哪裡設定？」，讓系統直接指出檔案和行號。條件是程式碼不能離開電腦，所以模型、向量資料庫全部在本機執行。

開發交給 Claude Code，一週合併了 25 個 PR、留下 20 份技術決策紀錄。我負責決定方向、部署除錯、review 每個 PR。

真正有意思的是實驗。我做了自動化評估，每次只改一個開關，跑了 8 組對照實驗：

✅ 分類取回：限制文件最多佔 1 段，文件佔比 95% → 25%，幾乎零成本，唯一採用
❌ 混合檢索：單看以為很有效，加了對照組才發現是別的開關的功勞
❌ 相似度門檻 0.70：套在程式碼上會丟掉 94% 的正確片段
❌ Rerank：首字延遲多約 10 秒，改善不穩定
❌ 防幻覺 prompt：陷阱題都拒答了，但可回答的題目也誤拒 8/9

學到的三件事：
1. 要有對照組，不然很容易把功勞算錯
2. 網路上的建議數字，要用自己的資料驗證
3. 指標要成對看，拒答率漂亮不代表系統有用

下一步：讓 AI 開發工具在改程式前先查詢這個系統，改得更準、減少幻覺。

完整的程式碼、實驗數據和決策紀錄都公開在 GitHub，連結放在留言。

#RAG #LLM #AI輔助開發 #ClaudeCode #軟體工程
I spent US$100 of AI cloud credits building an on-prem codebase Q&A system in one week.
The surprise: I tested 6 popular RAG techniques and kept only 1.

The goal was simple. Ask "Where is the invincibility time set?" and get the file and line numbers back. The constraint: source code never leaves the machine, so the model and vector database all run locally.

Claude Code did the building: 25 merged PRs and 20 architecture decision records in a week. My job was direction, deployment, debugging, and reviewing every PR.

The interesting part was the experiments. I built automated evaluation and changed one switch at a time across 8 controlled runs:

✅ Split retrieval (cap docs at 1 excerpt): doc share 95% → 25%, almost free. The only one adopted.
❌ Hybrid search: looked great alone, but a control group showed another switch deserved the credit
❌ A 0.70 similarity threshold: dropped 94% of correct excerpts on code
❌ Rerank: about 10 s more time to first token, unstable gains
❌ Anti-hallucination prompt: refused every trick question, but also refused 8 of 9 answerable ones

Three takeaways:
1. Always run a control group, or you will credit the wrong change
2. Validate popular thresholds on your own data
3. Read metrics in pairs: a perfect refusal rate can hide a useless system

Next: let AI coding tools query this system before they change code, so edits are more accurate and hallucinate less.

Code, experiment data and decision records are public on GitHub (link in the first comment).
